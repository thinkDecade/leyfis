Three admin roles — one panel, role-gated by wallet
ARCHITECTURE
Vault Operator
AMINA Bank or any institution deploying a Leyfis-wrapped vault. Configures the vault: sets minimum clearance tier, manages trusted issuers list, can pause the gate. Full read/write on their vault config. This is the pilot customer role.
KYC Issuer
The entity authorised to issue SAS attestations — could be AMINA Bank's compliance team, Blockpass, or a mock issuer for demo. Issues attestations to wallets, sets tier and expiry, can revoke instantly. This is the compliance officer role.
Compliance Auditor
Read-only. The regulator, internal audit, or compliance officer who needs to inspect activity. Can filter the audit log, view gate decisions, see attestation status, and export FATF-formatted reports. No write access to anything. This is what you show FINMA.

6 admin screens — what gets built
FRONTEND SCOPE
1
Admin gate — wallet-based role detection
Connect wallet → system reads which role that wallet holds on-chain → routes to correct dashboard view. No passwords. No user accounts. Wallet IS the identity. Role stored in VaultConfig authority field + KYC issuer registry.
CRITICAL
2
Vault operator dashboard
Live stats: total gate calls today, approval rate, denied count. Vault config panel: current min_tier, trusted_issuers list, pause toggle. Quick view of last 10 audit entries.
DEMO DAY
3
KYC issuer panel
Issue attestation form: wallet address, tier selector (1/2/3), expiry date, jurisdiction code. Active attestations table with revoke button per row. Revocation is instant on-chain. This is the mock KYC flow for the demo.
DEMO DAY
4
Audit log explorer
Full on-chain audit log in a table. Filterable by: wallet address, date range, outcome (approved/denied), tier, reason code. Each row expandable for full entry detail. Solana Explorer link per transaction.
DEMO DAY
5
Compliance report exporter
Date range picker + export button. Generates CSV with all FATF R.16 fields: wallet, timestamp, outcome, tier, attestation ID, issuer, jurisdiction. This is the document you hand to a regulator.
DEMO DAY
6
Attestation registry
All issued attestations: wallet, tier, issuer, issued_at, expires_at, status (active/expired/revoked). Searchable by wallet address. Gives AMINA Bank a live view of their verified wallet population.
POST-MVP
On-chain additions needed in the Gate Program
PRD UPDATES
Add pause instruction to VaultConfig
VaultConfig needs a paused: bool field. Gate checks this first — if paused, all transactions rejected regardless of attestation. Vault operator can toggle. Critical for emergency response.
Add update_vault_config instruction
Vault operator needs to be able to change min_tier and trusted_issuers post-deploy. Currently the PRD only has initialize. Add update instruction, authority-gated.
Add KYC issuer registry account
A small on-chain account that maps issuer pubkeys to roles. Lets the admin UI detect which wallet is a KYC issuer without hardcoding. Needed for wallet-based role detection in the admin gate.
How admin strengthens the Demo Day story
PITCH ANGLE
The admin layer turns a technical demo into a complete business product. Without it, judges see a Solana program. With it, they see:

AMINA Bank's compliance officer opens the KYC issuer panel, issues a Tier 3 attestation to a wallet, and it's live on-chain in seconds.

AMINA Bank's vault operator opens the dashboard, sees 12 gate calls today, 11 approved, 1 denied with reason TierInsufficient.

Their regulator opens the compliance export, downloads a CSV with every access attempt timestamped and FATF-formatted. No phone call needed. No manual report.

That three-role story is worth $100,000 to AMINA Bank. A lone gate program is not.
